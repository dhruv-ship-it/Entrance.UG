# Test Ecosystem

Entrance UG contains multiple independent assessment modules.

Although each pillar has its own tables and business logic, all assessment modules use the same core Test Engine.

The engine should therefore remain generic while reading and writing only to the tables of the corresponding pillar.

---

# Shared Test Engine Features

Every assessment module supports the following capabilities.

- Timer
- Auto Submit
- Question Palette
- Section Navigation
- Previous / Next Navigation
- Flag for Review
- Clear Response
- Mark for Review
- Auto Save
- Review Before Submit
- Single Correct MCQ
- Multiple Correct MCQ
- Integer Type Questions
- Positive Marks
- Negative Marks
- Section-wise Timer (if available)
- Test Timer
- Question Images
- Explanations
- Correct / Incorrect / Unattempted calculation
- Percentage
- Accuracy
- Rank
- Percentile
- Section-wise analysis
- Question Review
- Analytics
- Charts

The UI and business flow should remain identical across all pillars whenever possible.

Only the underlying tables change.

# General Rules

The test engine must never mix tables from different pillars.

Example:

A Mock Test must only write into:

- mock_attempt
- mock_attempt_section
- mock_attempt_answer
- mock_attempt_analytics
- mock_section_analytics

A Content Test must never update Mock tables.

A Mentorship Batch Test must never update Content or RC tables.

Each pillar owns its own data.

---

# Analytics Rule

Whenever a student submits an assessment:

1. Store the raw attempt.
2. Store every answer.
3. Calculate attempt statistics.
4. Update the analytics tables belonging to that pillar.
5. Never calculate analytics from the frontend.
6. Analytics should always be generated by the backend.

---

# Design Principle

The Test Engine should be reusable.

Only the following should change between pillars:

- Database tables
- Access table
- Navigation hierarchy
- Analytics tables

Everything else should behave consistently.
